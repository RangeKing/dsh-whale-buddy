# 0.2.2 live DSH acceptance

Verified on 2026-09-26 against the production plugin at commit
`dd698e50e9a6a02fac4f27d50bb62ef7ea0446e2`.

Environment: local DSH Web and `dsh-client-ui-chat` 0.1.5-rc.3, web profile
linked to this checkout, DeepSeek-V4-Flash / Low, dark theme. DSH was started
on loopback port 8080. Browser authentication tokens are omitted.

A dedicated “鲸鱼插件界面验收测试” session ran read-only commands and file
inspection in the existing test workspace. A second turn kept a command
running for 30 seconds to inspect the UI while switching the classic setting.

Observed results:

- The actual session and Dock both reported `working:running`. The inline,
  collapsed, and expanded whale renderers all carried the `wrench` prop.
- With classic status on, the existing DSH status row said `Deep diving...`
  and retained its elapsed clock; the plugin did not add a duplicate row.
- Turning classic status off mid-command restored `执行命令中...`; turning it
  back on restored `Deep diving...` without changing the task animation.
- The settings hint read `在输入框上方显示 Deep diving...`.
- After the turn completed, there were zero inline whales and zero status
  rows, exactly one Dock, and its activity was `idle`.
- The expanded panel closed normally and restored the compact Dock button.

The packaged code required no further change after this live check. The
0.1.7 host shape remains covered by production-bundle React integration tests
and the browser preview with simulated DSH signals; it was not a live 0.1.7
host in this acceptance run. Typechecking, build and all 176 tests passed
before the 0.2.2 release.
